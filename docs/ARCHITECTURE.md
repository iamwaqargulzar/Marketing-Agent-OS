# Architecture

Marketing Agent OS separates source preservation from runtime distribution.

## Installable layer

`skills/` contains 243 uniquely named, portable Agent Skills, and `catalog.json` is the discovery inventory. Both, along with `agents/`, are generated by `scripts/build_skills.py`. 222 skills carry an upstream skill's complete instructions and references, `marketing-os` is the router, `geo-update` is a local rewrite, and 19 earlier names are short pointers to their replacements.

The build does the following for each skill:

- copies the instructions, references, and templates, and leaves out evals and tests;
- rewrites links so the folder works alone, copying in directly linked shared files and pointing at sibling skills by relative path;
- renames upstream identities and host-specific paths, and removes promotions and sponsor markers;
- bundles only the helpers the skill's own steps use, and lists the excluded ones in the skill's helper notes;
- adds `LICENSE.txt` and `NOTICE.md` for its source, then appends the skill's `overlays/` additions and the shared operating rules.

The router carries every source file in four deterministic archives. Original runtimes retain their directory layouts, executable modes and license files. The router also ships the validator and the generated agent briefs for skills-only hosts.

`schema/`, `tools/`, `references/`, and `assets/` provide structured-data templates, optional connector contracts, governance rules, and reusable context. The root `.claude-plugin/` files expose the same installable layer as a Claude Code plugin without duplicating the payload.

## Source layer

`upstreams/source-a` through `source-d` preserve all tracked entries from four exact Git commits. `upstreams.lock.json` authenticates each snapshot with the repository URL, commit, entry count, license, and a cross-platform tree hash. Symlink payloads are normalized in that hash so validation remains stable on Windows checkouts that materialize symlinks as ordinary files.

The updater replaces only source snapshots. A separate build regenerates the installable layer, and the generated diff is reviewed before release.

## Distribution layer

`scripts/install.py` projects selected skills into a target harness directory. `install.sh` and `install.ps1` provide Linux/macOS and Windows entry points. Installation is staged and replaced atomically, validates requested names against the catalog, and includes the router library when installing specialists.

The universal target uses `.agents/skills`; native projections cover hosts with different discovery paths. Selective installation is preferred when a harness has a tight context or discovery budget.

## Integrity layer

- `scripts/doctor.py` validates skill metadata, catalogs, links, licensing, naming and promotion rules, build freshness, JSON, upstream pins, and the release hash manifest.
- `scripts/reconcile_upstreams.py` proves that every declared upstream skill name is represented by the normalized layer.
- `SHA256SUMS.json` detects any unrecorded package change.
- `tests/test_package.py` exercises installers, wrappers, validators, security boundaries, helpers, and source reconciliation.
