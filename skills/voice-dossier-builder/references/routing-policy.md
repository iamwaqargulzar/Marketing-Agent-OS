# Routing and Conflict Resolution

## Precedence

1. **User objective and explicit constraints** beat all source defaults.
2. **Safety, permission, evidence and claims truth** beat speed or source-specific conventions.
3. **Product marketing context** supplies durable strategic inputs.
4. **Specialist skill** beats generic orchestrator instructions for its bounded domain.
5. **Current first-party platform documentation** beats static tactics for time-sensitive SEO, ads, email, privacy or API behavior.
6. **Compatibility aliases** preserve upstream names but delegate to the canonical workflow.

## Resolved upstream conflicts

- GEO is a deep SEO/AI-discovery specialization, not a competing marketing operating system. `geo*` names remain available for compatibility.
- Product-marketing context is a shared dependency, but downstream skills may proceed with explicit assumptions when the missing context is non-blocking.
- Marketing Agent OS evidence, permission and registry governance applies to all skills.
- Claude-specific executable/plugin behavior lives in adapters; canonical `SKILL.md` files remain Agent Skills portable.
- Promotional footers and vendor/community upsells from upstream projects are not execution requirements. Attribution lives in `NOTICE.md`.
- Time-sensitive SEO/AI-search rules are not frozen into universal truth. Skills require live verification when eligibility or platform behavior matters.
- Duplicate skill names are merged by scope; source-specific names that encode narrower workflows are compatibility aliases rather than duplicate competing instructions.
